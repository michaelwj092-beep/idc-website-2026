# Technical Standards — A2
**UNIVERSAL · ALL STYLE TIERS · 2026 EDITION**
inspiredesignscollective.com

---

## MOBILE-FIRST STANDARDS
- Design and build mobile-first at 390px viewport — iPhone 14 is the baseline device
- Every layout decision is validated at 390px before considering desktop
- Touch targets are minimum 44px by 44px — no exceptions
- Sticky header collapses appropriately on scroll — no giant nav bars eating screen space
- Text is minimum 16px on mobile — never smaller for readability reasons
- Images use max-width: 100% — never overflow their containers
- No horizontal scrolling on any device at any viewport width

---

## SEO BASELINE — REQUIRED ON EVERY BUILD
- Meta title: Church Name + Location + Core Identity — 50 to 60 characters
- Meta description: 150 to 160 characters, includes primary keyword, reads naturally
- H1 tag on every page — one only, never more than one per page
- Alt text on every image — descriptive, not keyword-stuffed
- Page speed target: Lighthouse score 85 or above on mobile before delivery
- Google Search Console verified before handoff
- Sitemap.xml generated and submitted

---

## ASSET & FOLDER STRUCTURE
- Client folder in Supabase: /raw-media/ /approved-assets/ /brand/ /deliverables/ /revisions/
- All approved photos exported at 2x resolution minimum for retina displays
- WebP format for all web images — JPEG fallback for older browser support
- Logo delivered in SVG format — vector file required before build begins
- Brand style guide generated by IDC if client does not have one — always included

---

## FORM PLATFORM STANDARDS
Forms are never custom-built. All forms use approved third-party platforms. Custom form code introduces maintenance burden, security risk, and reliability issues that IDC does not support.

- Approved platforms: Planning Center Forms, Jotform, Google Forms
- Giving integrations: Tithe.ly, Pushpay, Subsplash — embedded or button link only
- Event registration: Planning Center Calendar is the standard recommendation
- Never build a custom event calendar — always connect to an existing platform
- Contact forms: embed from approved platform or use platform button link

---

## REQUIRED SITE ELEMENTS
- Branded 404 page — required on every build, every tier, no exceptions
- Favicon: auto-generated from church logo, square format, minimum 512x512px
- OG image: 1200x630px, includes church name and a strong image, auto-generated
- Privacy policy page — linked in footer, required for any site collecting form data
- Contact information in footer — address, phone or email, linked social accounts
- Service times in footer as well as at or near the hero — findable everywhere

---

## COMPONENT AUDIT OUTPUT FORMAT
When auditing a build report: PASS / FAIL / FLAG per component.
- PASS = meets standard
- FAIL = must fix before delivery
- FLAG = acceptable with documented reason

Every FLAG must have a note explaining why deviation was approved.
